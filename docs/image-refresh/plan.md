# 기술 블로그 이미지 교체 실행 기록

## 목표와 결정

현재 `_wiki`의 모든 문서(미커밋 Real_MySQL 포함)의 이미지를 본문과 원본을 함께 읽고, **내장 생성형 이미지 도구로 개별 제작**하여 교체한다. SVG/코드 그림으로 대체하지 않는다. 전체 범위는 최초 조사 기준 61개 문서, 이미지 사용 문서 36개, 참조 이미지 272개, PNG 273개다. 실제 manifest를 기준으로 신규·변경 문서도 조사한다.

기존 본문·사용자 변경은 보존한다. 자동 pull/reset, 커밋, 푸시, 공개 배포, Git 이력 삭제는 하지 않는다. 검수된 이미지에 한해 참조를 바꾸고, 참조가 없어진 원본과 배포 사본을 제거한다. 참조되지 않는 원본 1개는 용도 확인 후 별도로 정리한다.

## 제작과 검수

1. `manifest.json` 목록과 실제 Git/파일 상태를 대조한다. manifest 초기화는 한 번만 수행하고 재개 시 덮어쓰지 않는다.
2. 문서 전체를 읽고 각 원본을 `view_image`로 확인한다. 의미, 필수 텍스트·수치·연결 관계와 alt를 `specs/<id>.json`에 기록한다. OCR/캡션만으로 이해했다고 표시하지 않는다.
3. 흰 배경, 짙은 글자, 파랑·청록 강조, 평면 도형, 넉넉한 여백, 정확한 식별자를 공통 기준으로 삼는다. 이미지 언어는 문서에 맞춘다. 원본 배치·장식을 복제하지 않고 개념 명세로 새로 구성한다.
4. 가상 메모리 구조, Strategy Pattern 관계도, MySQL 아키텍처를 먼저 제작·검수한다. 이후 문서 단위로 모든 이미지를 순차 처리한다.
5. 명세의 `prompt`를 내장 `image_gen`에 전달하고 출력 파일을 프로젝트의 기존 img 폴더에 `<원본이름>-generated.png`로 복사한다. 생성 도구의 실제 반환 경로를 사용한다. CLI/API로 임의 전환하지 않는다.
6. 생성물을 직접 보고 모든 필수 텍스트, 수치, 화살표 방향, 관계와 단계 순서, 잘림, 가독성을 확인한다. PNG 디코딩도 별도 확인한다. 검수 내용을 `reviews/<id>.json`에 기록한다. 실패한 결과는 교체하지 않는다. 최대 세 차례 수정 후에도 실패하면 미완료 상태로 남겨 다른 이미지를 계속 처리하고 추후 재검토한다.
7. 검수 증거를 저장한 후 `apply`, 그 후 `retire`로 교체 및 원본 정리를 수행한다. 임의로 상태 문자열만 완료로 바꾸지 않는다.

## 재개와 명령

저장소 루트에서 `node scripts/image-refresh.cjs <command>`를 사용한다.

- `scan`: 최초 manifest 생성 또는 새 이미지 추가. 이미 기록된 항목의 상태를 보존한다.
- `status`: 전체 진행 수와 다음 미완료 항목.
- `spec <id> <명세 JSON 경로>`: 원본/본문 확인과 명세 저장.
- `import <id> <생성 PNG 절대 경로>`: PNG 검사 후 프로젝트에 복사, 생성 이력 저장.
- `review <id> <검수 JSON 경로>`: 현재 생성 파일의 해시와 검수 증거 연결.
- `apply <id>`: 통과된 검수의 해시·원본 참조를 재확인하고 Markdown 이미지/alt/크기만 교체.
- `retire <id>`: 전체 문서의 원본 이미지 참조가 없고 새 이미지가 검수된 상태일 때 원본·배포 사본 제거.
- `audit`: 실제 참조·파일·해시와 manifest를 검사. 미완료를 완료로 보고하지 않음.

명세 필수 필드: `originalViewed: true`, `documentReviewed: true`, `purpose`, `requiredChecks`(문자열 배열), `alt`, `prompt`. 이미지의 세부 수치/텍스트/연결을 정확히 기록한다.
검수 필수 필드: `viewed: true`, `decoded: true`, `passed: true/false`, `checks`(명세와 같은 순서로 `{requirement, passed, evidence}` 배열), `notes`. 이미지와 본문을 실제로 대조한 구체적 관찰을 evidence에 기록한다.

## 완료 검증

- 전체 272개를 포함한 최신 목록이 모두 교체·원본 정리 완료여야 한다. 검수 미완료나 실패가 있으면 목표를 완료하지 않는다.
- 모든 생성 파일 디코딩, 이미지·Markdown 참조·배포 경로, 본문 보존, HTML 크기 비율, 누락 파일과 원본 잔존을 검사한다.
- 사이트 생성기는 이미지 크기 문법을 HTML로 반영하고 참조 이미지 파일을 `public/wikis`의 문서 상대 위치에 복사한다. URL 구조는 유지한다.
- 모바일에서는 복잡한 도식의 글자가 작아지므로 생성 이미지를 클릭하면 해당 PNG를 새 탭에서 크게 볼 수 있도록 한다. 기존 명시적 이미지 링크는 보존한다.
- 모든 새 이미지를 개별 검수하고 모든 대상 HTML의 이미지 로딩을 확인한다. 대표 페이지는 넓은 화면과 모바일 폭에서 시각적으로 확인한다.
- 의미 있는 생성기/교체 안전성 회귀 테스트, `git diff --check`, 진행 보고서를 남긴다.

## 사용량과 자동 재개

이 채팅에 heartbeat `블로그 이미지 교체 이어서 작업`(id: `automation`)를 등록했다. 한국시간 01:41, 06:41, 11:41, 16:41, 21:41에 재개 가능 여부를 확인한다. 최초 확인된 5시간 초기화 시각은 2026-10-13 01:39:54 KST다.

매 실행에서 실제 usage limits를 확인한다. 한도 소진 시 초기화 이후로 예약을 조정한다. 사용량 리셋 크레딧을 임의 소비하지 않는다. 재개 시 실제 진행과 현재 도구 핸들을 확인하고, 아직 살아 있는 생성 호출을 중복 실행하지 않는다. 현재 실행 중인 프로세스/호출만 대기로 인정한다. 전체 완료 후에만 목표 완료 및 자동화 비활성화. 알림은 완료·실패·사용자 조치 필요시에만 보낸다.
