# 이미지 교체 후 독립 재검토

2026-10-13. 이미지가 포함된 문서 36개와 신규 이미지 272개를 직접 검토했다. 확보한 원본 267개는 인벤토리 SHA-256과 일치하는 픽셀을 복구해 신규 이미지와 나란히 비교했다. 문서의 설명, 코드, 표와 도식의 요소·수치·화살표·관계를 함께 확인했다.

바이너리 로그 캐시는 연결별로 할당된다는 [MySQL 공식 설명](https://dev.mysql.com/doc/refman/8.0/en/replication-options-binary-log.html)과 [메모리 사용 문서](https://dev.mysql.com/doc/refman/8.0/en/memory-use.html)를 확인했다. 수정 PNG는 전체 해상도로 다시 읽고 디코딩했으며, 이전 이미지·규격·승인 기록과 해시를 별도로 보존했다.

## 문서와 도식의 일치

- CPU Scheduling: 지수 평균의 실측값 `t_n`과 기존 예측값 `tau_n`을 구분하고 수식을 수정했다. [대학 강의 자료](https://www.ics.uci.edu/~ics143/lectures/oslectureset3-spr20.pdf).
- Virtual Memory: 유효한 주소를 종료한다고 뒤집혀 있던 페이지 폴트 분기를 수정하고, EAT의 `(1-p)` 괄호를 복원했다. 해당 문서의 정상 도식과 이어지는 계산 예제에 맞췄다.
- Relational Model: `section.time_slot_id`의 시간대 연관 방향과 복합 기본키 때문에 단일 컬럼 외래키로 선언할 수 없다는 설명을 바로잡았다. [교재 저자의 자료](https://www.db-book.com/slides-dir/PDF-dir/ch4.pdf).

문서 본문 변경은 이유와 변경 전후 해시를 `manifest.json`의 `documentBaselines[].amendments`에 기록했다. 기존 본문 기준 해시를 보존해 변경 이력을 추적할 수 있다.
